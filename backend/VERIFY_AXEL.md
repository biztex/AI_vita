# AXEL 品質の確認方法 / How to verify AXEL quality

AXELの応答品質・画像解析・音声解析を、いつでも確認できる2つの方法です。

---

## 方法A：自動検証ツール（コマンド1つ）

実際のAIエンジンを呼び出し、5つの能力を検証して、実際の返答をそのまま表示します。

```bash
cd /home/dev/Documents/project_ex/AI_vita/backend
npm run verify:quality
```

（または `npx tsx scripts/verify-axel-quality.ts`）

**検証される項目：**

| # | 項目 | 確認内容 |
|---|------|----------|
| 1 | 情報の質問 | 質問の意図をまず受け止める／最新情報は正直に確認先を案内 |
| 2 | 判断の相談 | 論点・選択肢・メリデメ・リスク・見立ての深掘り／利用者情報を反映／性格タイプ記号を言わない |
| 3 | Web検索 | 最新情報を検索／**公式(go.jp)を優先して出典表示**／偽サイトを公式と誤表示しない |
| 4 | 画像解析 | 画像の内容を読み取り、利用者の事業に結びつけて回答 |
| 5 | 音声解析 | 音声を日本語で正しく認識し、相談として応答 |

各セクションで **実際のAXELの返答が全文表示** されるので、チェックマークだけでなく
「返答の質そのもの」を目で確認できます。

- 本番データには一切触れません（一時ファイルを使用、実行後に自動削除）。
- 実際のOpenAI APIを使うため、1回の実行で少額のAPI利用料がかかります（数十円程度）。
- 所要時間：2〜4分。

---

## 方法B：LINEで実際に試す（本番同等の確認）

デプロイ後、LINEのトーク画面で以下を送って確認します。文字・画像・音声の
どれも「そのままトークで送るだけ」です。

### 1. 文字（情報の質問）
> IT導入補助金は今年も申請できますか？公式の申込先も教えて

**良い応答の目安：** 最新の状況に触れ、**go.jp の公式サイト**を出典として案内し、
確認できないことは「確認できない」と正直に言う。偽の類似サイトを「公式」と言わない。

### 2. 文字（判断の相談）
> 幹部を1人採用すべきか、資金を製品開発に回すべきか迷っています

**良い応答の目安：** 論点整理 → 選択肢（メリット・デメリット）→ 注意点 →
あなたに合うか → 見立て、まで構造的に踏み込み、あなたの事業・目標を踏まえている。

### 3. 画像
広告や書類の写真を送り、「これについて相談したい」と送る。

**良い応答の目安：** 画像の内容（金額・条件など）を正しく読み取り、
あなたの状況に結びつけて助言する。不鮮明なら推測せず再送を求める。

### 4. 音声
相談内容を声で吹き込んで送る。

**良い応答の目安：** 話した内容を正しく認識し、文章で自然に応答する。

### 確認したい観点（クライアント提示の6項目）
- 情報の正確性（出典・公式優先）
- 回答の具体性
- 利用者情報の反映
- 判断支援の深さ
- 会話の自然さ
- 専属コンシェルジュとしての個別性

---

## 補足
- 方法Aは「開発側での再現確認」、方法Bは「実機での最終確認」に向いています。
- 気になる応答があれば、その画面（スクリーンショット）を共有いただければ、
  該当の挙動を調整します。
